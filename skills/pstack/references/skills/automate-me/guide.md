# Capture a working style

Use when the user asks for a personal mode or working-conventions skill. This does not create scheduled automations.

Study the relevant current conversation, supplied history, and permitted project-scoped Codex chat reads. Require repeated evidence for a habit; preserve explicit user preferences without widening them. Ask a few focused preference questions only when the record cannot settle them.

Group only concrete non-default preferences about communication, scope, ownership, verification, and tools. Do not clone pstack's rules or install another authority document.

Use **skill-creator** to draft `.agents/skills/<handle>-mode/SKILL.md` in this project unless another location was requested. Use a precise trigger and supported YAML. Automatic selection stays at the host default unless the user explicitly asks for an explicit-only skill.

Show concrete content and iterate when user feedback matters. Do not edit global memory/configuration, create a worktree, commit, publish, or open a PR merely as a completion ritual. Verify the new skill's packaging and references and explain what has and has not been behaviorally tested.
