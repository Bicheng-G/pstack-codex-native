# multi-phase-plan

The deliverable is a plan. Do not implement unless the user also requested implementation.

Ground scope, ownership and dependencies from source. Settle observable factual questions through existing evidence or a scoped authorized prototype, and reserve product/preference decisions for the user. Compare material alternative shapes with **architect** when needed.

Plan independently verifiable units in dependency order. For each record intended behavior, affected files/interfaces, prerequisite, build/change steps, actual validation method, evidence/pass predicate, rollback/recovery needs, user gates, and intended delivery state. Use unit/live/perf checks when relevant; justify an inapplicable lane rather than inventing a ritual.

Name who owns shared state and stack topology, permitted delegation, and the done predicate. Keep a normal plan in context; save a file only when requested or necessary for execution/recovery. The plan itself creates no execution rights, schedule, model budget, or merge authority.

Return the concrete sequence, tradeoffs, unresolved decisions, and how progress will be checked. The original fixed ten-lane plan schema and its checker are not used in this adaptation.
