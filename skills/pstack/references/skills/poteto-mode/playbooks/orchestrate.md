# orchestrate

Reserve this for an explicitly requested standing multi-unit program. A task one agent can finish uses autonomous-run. Establish scope, acceptance, actual grants, concurrency budget, ownership, and user gates before fan-out.

Keep one canonical small program record only when cross-context coordination warrants it: units, owner, checkout/branch, PR, exact head, state, brief/evidence pointers, verification receipts, and unresolved gates. Derive status from those facts instead of maintaining competing narratives. This adaptation uses ordinary files and Codex agent state, not an orchestration database CLI.

Give every unit a standalone brief with goal, authorized writes, source pointers, acceptance, actual verify commands, stopping budget, forbidden actions, and report schema. Isolate writers. Pilot the full path on one representative unit before scaling novel work.

Use native bounded agents up to the current slot limit. After a completion, record the receipt, validate dependency context, verify material work, and refill ready slots. Account for every child, including failed/abandoned ones. Do not hide missing coverage by silently doing its work.

One owner may change a stack's topology. Workers never acquire merge/rebase/publication authority merely from a role. Verification receipts key to artifact/PR plus exact base/head and method. Recheck changed verified inputs. Integrate or land only within the user's delivery grant.

On stalls use bounded evidence-driven retries; reduce scope or stop with a precise handoff when the same block persists. On recovery re-read actual agent/process/Git/forge state; do not assume sessions or cloud machines survived.

A requested recurring program check uses Codex automations, stays quiet on unchanged state, and stops/archives only under the relevant request. No scheduler is installed automatically.

Report completed/total units from the canonical record, current frontier, verified and unverified work, gaps, gates, and recovery paths.
