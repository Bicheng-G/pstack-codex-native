# runtime-forensics

The deliverable is diagnosis. Pin the live symptom and environment. Inspect existing instrumentation and capture safe runtime evidence of the actual leak, spin, glitch, or stall. Separate process liveness from useful progress.

Correlate traces with state transitions and source ownership. Form falsifiable hypotheses and use bounded probes. If adding instrumentation changes files, confirm that it lies within the requested diagnostic scope. Report the supported cause, alternatives ruled out, remaining unknowns, and a proposed fix without silently implementing it.
